# 首轮原生分辨率推理的内存诊断

## 已确认事实

- 权重已校验；native-v2 的加载耗时为 25.31 秒。程序到达第一个去噪步骤，随后在 apply_rotary_emb 的 FP32 临时张量计算处报 OutOfMemoryError。完整失败保存在 native17-failure.json。
- 原输入为 17 帧、480×720，guidance_scale=6，启用双路 classifier-free guidance；已使用 BF16、逐层 CPU 卸载、VAE 切片与平铺。
- 当前 GPU 空闲时没有其他计算进程。该检查不能证明故障发生时不存在驱动或系统内存预算影响。
- 内核探测显示 Flash Attention 不可用，但 EFFICIENT_ATTENTION 与 MATH 对小型探测张量可运行。探测不能证明上次真实推理选择了哪一个内核，更不能将无 Flash Attention 单独判定为根因。
- 故障同时报告 2.50 GiB 空闲和 160 MiB 分配失败，仅凭该日志不能把原因完全确定为物理显存耗尽；Windows 驱动分配预算或系统提交内存也仍需排查。

## 本轮调整

保持 480×720，使用独立的 9 帧输入与新输出目录。guidance_scale=1，关闭动态 CFG，避免双路拼接；强制 EFFICIENT_ATTENTION，使内核不可用时明确失败，避免静默回退。记录加载前后、每个去噪步骤及失败时的显存数据。28 项接口与核心测试通过。

这是同时改变多项参数的可运行性诊断，不是因果消融，也不是与上轮同预算的画质对比。成功后需要逐项恢复帧数与引导强度，才能判断各因素影响。
