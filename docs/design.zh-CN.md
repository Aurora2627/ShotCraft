# 系统设计 v0.1

## 实际需求

短视频后期制作中，镜头已经拍好，但出现穿帮物体、杂物或需要替换的局部道具。重新拍摄成本高，希望只修改指定对象，保留人物、其他物体、镜头运动与原声。

首期输入为单个 3—10 秒镜头，人工提供逐帧二值掩码或经确认的跟踪结果，支持目标移除。通过后再增加参考图局部替换、自动目标定位和跨镜头任务。完整长视频能力需单独验收，不沿用上游宣传直接视为本系统能力。

## 系统边界

- VideoPainter：底层视频补全/编辑生成、上下文分支、上游 ID resampling；原方法属于上游。
- 我们的系统：任务与保留约束、视频/掩码校验、镜头调度、掩码质量控制、自研可训练模块、评测筛选、失败处理、结果预览与审计。
- 生成后端实现统一接口，后续可换模型；不得将其他模型的结果标记为 VideoPainter。

## 数据流

编辑请求 → 视频解码和时间范围校验 → 镜头边界 → 目标掩码/保护区域 → 掩码控制器 → VideoPainter 后端 → 原始候选评测 → 可选保护区域合成 → 合成后评测 → 人工确认导出。

音频单独保留，按输出实际时间轴重封装。发生变帧率、帧丢失或时长变化时必须检测，不直接复制音轨制造音画不同步。

## 自研算法主线：时序掩码残差控制器

固定膨胀掩码作为 baseline。我们拟训练轻量时空残差网络，依据 RGB、传播掩码、双向光流和传播不一致性，修正移动和遮挡边缘。保护区域作为显式输入与推理约束。

第一版采用小型 Conv3D 残差头，输出掩码 logit 的残差，末层零初始化。初始参数没有训练效果，不能当成算法成果。训练数据用真实目标分割掩码作为监督，将其腐蚀、错位、漏帧等生成退化输入；训练/验证/测试按原视频隔离，禁止相邻帧跨划分。

拟定损失为 BCE + Dice，再研究光流对齐后的时序约束和保护区域惩罚。必须与固定膨胀、仅空间网络对比，并将修正掩码送入相同 VideoPainter 权重/种子，检查实际编辑收益。掩码分割指标提升不自动等于生成质量提升。

## 自研工程模块

- 请求协议：编辑类型、时间范围、目标掩码、保留区域、提示词和种子。
- 镜头/窗口规划：不跨镜头传播目标身份；窗口有重叠且完整覆盖，最后短窗口明确补帧策略，输出时裁掉填充帧。
- 后端适配：单独进程运行上游依赖，记录上游 commit、权重哈希、资源耗时和失败原因；本仓库不直接修改上游源码。
- 质量门控：分别报告未编辑区域变化、编辑区域语义匹配、边界伪影、运动补偿后的时序误差；缺失指标显示未计算。
- 任务系统：请求幂等、GPU 串行队列、中断恢复、预算上限、失败重试与原/编辑对比。

## 评测协议

先确定 12 条开发视频排查输入和算力，正式目标为不少于 30 个独立视频、60 个任务，含静态、相机运动、目标运动、遮挡、细边界等。实际数量与来源在清单中记录，不提前填实验结果。

B0：原始 VideoPainter + 固定掩码。
B1：同一后端 + 固定掩码膨胀。
M1：同一后端 + 学习式时序掩码控制器。
消融：去时序信息、去不确定性输入、去保护约束。

保持源视频、编辑指令、生成步数和随机种子一致；质量和资源分别报告，额外多候选不得与单候选直接比较。先评测原始生成结果，再评测合成结果，避免像素拷贝让保护指标看起来完美。光流需遮挡/可见性筛选，直接帧差不能作为时序一致性结论。没有背景真值时不报重建 PSNR 作为编辑成功率；没有真人盲审时明确缺失，不伪造评分。

## 资源策略

Windows RTX 4060 8 GiB 负责业务代码、掩码控制器训练与评测开发。VideoPainter 使用 CogVideoX-5B-I2V、独立上下文分支及文本编码等，完整运行的显存与磁盘预算需实测；不能套用普通 CogVideoX 的低显存宣传。

依赖与其他项目隔离，不直接安装官方完整 requirements 覆盖现有环境。先审查推理最小依赖；DeepSpeed 等训练依赖不属于首期推理必须项。若 8 GiB 无法完成稳定推理，保留 Windows 开发与调度，在云 GPU 上运行相同后端；租用由用户决定。

## 阶段验收

A：协议、调度、自研模块与单元测试；保存上游和资源盘点。
B：真实 VideoPainter 基线生成一条视频，并保存可复跑命令与资源数据。
C：构建隔离数据集，训练掩码控制器，完成成对对照与消融。
D：完成审核与导出应用、任务恢复、评测看板和最终项目说明。
